Invoice to JSON API

Extract structured JSON from invoices, receipts, resumes, bank statements and more - with OCR, in English and Vietnamese.

Get your API key on RapidAPI API docs

What it does

Send supplied document text or supported base64 input and receive structured fields for review. Invoice results can include numbers, dates, vendor, totals and line items. Consumers do not need an LLM key. Missing or ambiguous fields can be null; extraction is not guaranteed to be complete or accurate.

Invoice, receipt, resume and bank-statement routes have a /base64 variant. Other routes accept content_type in their request body; see the reference for the exact supported request. OCR depends on document quality and installed language support.

Quick start

Subscribe on RapidAPI, set RAPIDAPI_KEY to your own consumer key, and run this POSIX-shell example. The gateway supplies provider authentication; direct backend calls are protected.

curl --request POST \
  --url 'https://invoice-to-json-extractor1.p.rapidapi.com/v1/invoice/extract' \
  --header 'Content-Type: application/json' \
  --header "X-RapidAPI-Key: $RAPIDAPI_KEY" \
  --header 'X-RapidAPI-Host: invoice-to-json-extractor1.p.rapidapi.com' \
  --data '{"content":"Invoice No: SYNTHETIC-001\nDate: 2026-10-11\nVendor: Synthetic Demo Ltd\nSubtotal: 100 USD\nTax: 10 USD\nTotal: 110 USD","content_type":"text","language":"en"}'

The tested synthetic example returns success: true, invoice.subtotal: 100, invoice.tax_amount: 10 and invoice.total: 110. This is one example, not an accuracy benchmark for your files.

Check arithmetic after extraction

Extraction and arithmetic checks solve different steps. Map tax_amount to tax, require subtotal and total, then use the Invoice Arithmetic Validator to report mismatched totals. Neither step proves invoice authenticity or tax compliance.
